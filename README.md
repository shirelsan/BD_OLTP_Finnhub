## 4. Verbal Analysis (ניתוח מילולי)

* **כמה קרובות היו התוצאות המקוונות לעומת הלא-מקוונות?**
התוצאות המקוונות היו זהות לחלוטין לתוצאות הלא-מקוונות (עד כדי הבדלים אפסיים הנובעים מעיגול ברמת הנקודה הצפה). הדבר מוכיח כי השימוש באלגוריתם Welford לחישוב השונות ובנוסחת ה-EMA הרציף מאפשר לדייק בסטטיסטיקות במאת האחוזים, מבלי להפר את האילוץ של אי-שמירת הנתונים בזיכרון.

* **עיכובים (Latency) או צווארי בקבוק שנצפו:**
לא נצפו עיכובים (Latency) משמעותיים בעיבוד המקוון. זמן העדכון של כל דגימה בודדת מתבצע בסיבוכיות זמן של O(1), כך שהמערכת התמודדה בקלות עם קצב ההודעות מה-WebSocket. צריכת הזיכרון באונליין הייתה מזערית לעומת האופליין שדרש 7.5135 MB. צוואר הבקבוק היחיד שניכר היה פעולת ה-I/O של כתיבת הטקסט לקובץ כל 100 הודעות, אך מנגנון זה תוכנן כך שלא יעכב את קריאת הזרם.

* **הודעות שנפלו או הודעות שגויות:**
במהלך קליטת הנתונים, השרת של Finnhub שלח שורות רבות של תקשורת WebSocket ו-Trace (כגון Rcv raw). בזכות מנגנון חילוץ ה-JSON הממוקד ששילבנו ובלוקי ה-try-except, המערכת ידעה להתעלם משורות אלו ומהודעות שגויות ללא קריסה. כל הודעה לא תקינה נרשמה אוטומטית בהתאם לאילוצי המטלה, והמערכת עיבדה את נתוני העסקאות נטו בהצלחה (כ-20,000 עסקאות שחולצו בצורה חלקה).
